# 법인 뉴스 이슈 트래커

![Type](https://img.shields.io/badge/Type-Internal%20Tool-purple) ![Status](https://img.shields.io/badge/Status-매일%20운영%20중-success) ![Period](https://img.shields.io/badge/Period-2026.09~현재-blue)

**Tech Stack:** Python, GitHub Actions, Claude Code(무인 실행), openpyxl, pytest

## Problem

증권사 법인 영업 부서는 수백 곳의 법인을 여러 팀이 나누어 관리합니다. 유상증자, 자산 매각, 재무 책임자 교체 같은 사건은 상품을 제안할 계기가 되지만, 담당자가 매일 그 많은 법인의 뉴스를 직접 확인할 수는 없었습니다.

관리 법인과 신규 후보 법인의 뉴스에서 영업에 의미 있는 사건만 골라, 매일 아침 팀별 엑셀 한 파일로 전달하는 것을 목표로 했습니다. 틀린 기사가 섞이면 담당자가 도구를 믿지 않게 되므로, 많이 싣는 것보다 틀리지 않는 것을 우선했습니다.

---

## 구조

역할과 권한을 나눈 세 단계의 에이전트가 규칙 기반 선별 뒤에 이어집니다.

| 단계 | 하는 일 | 제한과 검증 |
|---|---|---|
| 규칙 선별 (코드) | 뉴스 수집, 잡음 기사 제거, 중복 통합, 여러 법인에 걸린 기사 묶기 | 고정된 응답을 쓰는 테스트로 검사 |
| 판정 에이전트 (병렬) | 100건 단위 조각마다 기사 주체와 영업 분류를 판정하고 모든 항목에 사유를 기록 | 판정 파일 하나만 작성 가능. 검증 스크립트를 스스로 실행하고, 파이프라인이 항목 수와 순서를 다시 대조 |
| 검토 에이전트 | 요약을 "법인명, 핵심 사실, 수치" 형식으로 다시 쓰고 실행 보고서를 작성 | 판정 파일은 수정 불가 |
| 2차 점검 에이전트 | 최종 결과만 처음 보는 사람의 눈으로 다시 읽어 중복과 오매칭을 점검. 이전 7일의 결과와 대조해 재보도는 빼고 후속 보도는 표시 | 판단이 애매하면 지우지 않고 보고서에 기록 |

모든 에이전트는 허용된 도구 목록 안에서만 동작하고, 기사 본문에 적힌 문장은 판정할 데이터일 뿐 지시가 아니라는 규칙을 둡니다. 날짜별 판정 대상, 판정 결과와 사유, 최종 결과, 실행 보고서를 모두 보존해 어떤 기사가 왜 실리거나 빠졌는지 나중에 추적할 수 있습니다.

## 선택과 포기

| 선택한 것 | 포기한 것 | 그렇게 판단한 근거 |
|---|---|---|
| 관리 법인 기사는 전부 에이전트가 판정 | 자동 통과로 얻는 속도와 낮은 비용 | 키워드 조건만으로 자동 통과시킨 기사를 재현해 보니 6건 모두 반려 대상이었습니다 |
| 같은 사건의 다른 기사는 자동으로 묶지 않음 | 판정 대상을 더 줄일 기회 | 수치가 겹치는 기사가 연쇄적으로 이어져 무관한 기사 248건이 한 묶음이 되었습니다 |
| 판정이 하나라도 빠지면 결과물을 만들지 않음 | 그날 아침 결과물이 나가지 않을 수 있음 | 일부만 판정된 결과가 완전한 것처럼 전달되는 편이 하루 늦는 것보다 위험하다고 보았습니다 |
| 진행 중이거나 예고된 사안도 채택 | 확정된 사실만 싣는 단순한 기준 | 확정된 사건만 채택하자 담당자가 먼저 알아야 할 기사가 빠졌습니다. 대신 "추진", "예정", "검토" 표현을 그대로 살렸습니다 |
| 1차 검토 뒤에 2차 점검을 추가 | 실행 시간과 비용 | 1차 검토 뒤에도 같은 사건이 여러 행으로 남은 사례가 있었습니다 |

## 결과

- 2026년 9월부터 매일 운영 중이며, 부서의 모든 영업팀이 매일 아침 엑셀을 받아 보고 있습니다.
- 두 달간(9.17~11.16) 30,959건을 판정해 74%를 반려하고, 기존 법인 이슈 4,481건과 신규 후보 3,649건을 채택했습니다.
- 팀에서 보고 싶은 이슈 키워드를 요청받아 수집 조건과 분류에 반영합니다.
