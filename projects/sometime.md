# 썸타임 (Sometime)

![Status](https://img.shields.io/badge/Status-LIVE-success) ![Period](https://img.shields.io/badge/Period-2024~현재-blue) ![Revenue](https://img.shields.io/badge/Revenue-1억+-green) ![Users](https://img.shields.io/badge/Users-7,000+-blue)

**Tech Stack:** React Native, Nest.js, PostgreSQL, Redis, AWS, Naver Cloud

**서비스:** [썸타임](https://info.some-in-univ.com/)

---

## Overview

교내 창업 동아리 '한밭모'에서 시작하여 **초기창업패키지 딥테크**에 선정된 지역 기반 대학생 소개팅 앱입니다.

학교 축제에서 640명의 유저를 모으며 시장성을 검증한 후, Next.js 기반 초기 버전을 React Native와 Nest.js로 전면 리팩토링하여 현재 운영 중입니다.

---

## Journey

### Phase 1: Project-solo (축제 버전)

마감 일주일을 앞두고 시작한 첫 프로젝트. Cursor와 구글링으로 '일단 돌아가는' 것에 중점을 두고 개발했습니다.

- **결과:** 축제 2일간 640명 유저 확보
- **수익 검증:** 2,000원 부가기능에 30%가 결제
- **기술 스택:** Next.js, Supabase

### Phase 2: 썸타임으로 확장

시장성을 확인하고 자체 솔루션 구축을 결정. Supabase 의존성을 벗어나 React Native + NestJS로 전환했습니다.

- **확장:** 한밭대 → 대전권 전체
- **성과:** 초기창업패키지 딥테크 선정
- **팀 구성:** 개발자 추가 영입

### Phase 3: 위기와 재정비

인원이 늘어났지만 속도가 선형 증가하지 않았습니다. 커뮤니케이션 비용이 늘어나고 방향성이 흔들렸습니다.

재정 상황과 개발 속도 문제로 팀원들이 퇴사하고 선임개발자와 둘만 남아, **사무실에서 숙식하며** 서비스를 재정비했습니다.

## Problem Solving: 환불 문제 해결 사례

### 문제 상황

이성과의 채팅이 "안녕하세요" 같은 간단한 인사말 이후 두절되는 경우, 유저들이 환불을 요청했습니다. 운영팀에서 환불 프로세스 구축을 요청했습니다.

### 초기 접근

처음엔 환불 프로세스를 체계적으로 정의해야 한다고 생각했습니다. 자동화 시스템을 만들고, 조건을 명확히 하려고 했습니다.

### 근본 원인 분석

하지만 우리 서비스 상황은 여유롭지 않았고, 프로세스가 생각보다 복잡했습니다. 유저 설문을 분석해보니 환불 요청의 근본 원인은 **"무슨 말을 해야 할지 몰라서"**였습니다.

### 해결 방안

복잡한 환불 시스템 대신 최소 기능으로 구현했습니다:

1. 채팅이 열리고 48시간 동안 일정 횟수 이하의 대화만 오간다면
2. 구글폼으로 연결되는 버튼이 보이도록 추가
3. 유저가 구글폼을 신청한 이메일로 환불 절차와 브랜드 가치를 전달

### 결과

개발 리소스를 절약하고, **채팅 경험을 개선하는 데 집중**할 수 있었습니다. 사람 냄새가 나는 서비스를 만들고자 했습니다.

## What I Learned

### 비즈니스 가치와 기술적 완성도의 균형

스타트업에서 주 7일 숙식하며 개발했던 경험을 통해 **초기 성장의 속도와 장기적인 코드 품질 사이의 트레이드오프**를 체득했습니다.

### 팀 스케일링의 어려움

인원이 늘어난다고 개발 속도가 선형적으로 증가하지 않습니다. 커뮤니케이션 비용이 늘어나고, 같은 방향을 바라보게 하는 것 자체가 일이 됩니다.

### 서비스의 본질

서비스의 진짜 주인은 유저입니다. 우리가 만들고 싶은 서비스가 아니라, **유저가 원하는 서비스**를 만들어야 합니다.

개발 리소스를 쏟아서 기능을 만들었는데 유저가 별로 사용하지 않는다면? 지금 집중해야 할 곳에 집중을 못하고 있다는 뜻입니다.

### 개발자의 역할

개발자는 '일상의 문제를 기술적으로 해결하는 직업'입니다. 기술과 사업, 두 관점을 모두 보며 트레이드오프를 분간하고, 문제를 과하지도 약하지도 않게 풀어낼 솔루션을 제공하는 것이 중요합니다.
