# 리서치 맵

![Type](https://img.shields.io/badge/Type-Personal-blue) ![Status](https://img.shields.io/badge/Status-운영%20중-success) ![Period](https://img.shields.io/badge/Period-2026.08~현재-blue)

**Tech Stack:** Python(pypdf), Claude Code CLI, GitHub Actions, Vercel/Next.js

**저장소:** [github.com/YUJAEYUN/f_report](https://github.com/YUJAEYUN/f_report)

---

## Problem

그룹포탈에 기업분석·경제 시황·산업분석·테마분석 리포트가 매일 많이 올라오는데, 대부분 길고 긴 PDF라 전부 정독하기엔 시간이 너무 들었습니다. 요약만 보고 넘어가면 애널리스트의 매수 의견 쏠림을 그대로 받아들이게 된다는 게 더 큰 문제였습니다. 궁금한 건 매수·매도 의견 자체가 아니라, 그 의견에 이르는 논리였습니다.

---

## 구조

- **수집** (코드): 공개된 리포트만 크롤링합니다(하나증권·미래에셋 리서치 게시판, 한경 컨센서스로 메리츠·유안타·SK 등 10개사). 로그인 없이 공개된 목록과 PDF만, 요청 간격을 두고 수집합니다.
- **파싱** (코드): PDF를 통째로 저장하지 않고 pypdf로 텍스트만 추출합니다. 원문 텍스트는 `raw-text` 브랜치, 메타데이터는 main으로 분리합니다.
- **생성 세션**: Claude Code 스킬 12개로 요약, 산업 태깅, 테마 병합, 산업 브리핑, 주간 인사이트, 일간 다이제스트 등을 만듭니다.
- **평가 세션** (별도 LLM): 생성 세션과 완전히 분리된 세션이 리포트의 근거→결론 논리의 강점과 약점만 짚습니다. 대시보드에서 "AI 평가" 버튼을 누른 리포트만 평가해, 비용을 쓰는 곳을 직접 고릅니다.
- **운영**: 상시 서버 없이 GitHub Actions로 수집·가공하고, 결과를 git에 커밋하면 Vercel이 Next.js 대시보드를 재빌드합니다.

---

## 선택과 포기

| 선택한 것 | 포기한 것 | 그렇게 판단한 근거 |
|---|---|---|
| 요약 세션과 평가 세션을 완전히 분리 | 한 세션에서 요약과 평가를 함께 처리 | 평가가 생성 쪽 맥락에 끌려가면, 걸러내려던 매수 의견 쏠림을 그대로 반복하게 됨 |
| 투자의견·목표주가 같은 숫자 변화 추적은 코드로 계산 | LLM으로 변화 이벤트까지 판단 | 정형 데이터는 코드가 더 정확하고 저렴함 |
| 평가는 버튼을 눌렀을 때만 실행 | 모든 리포트를 자동으로 평가 | 비용을 쓸 곳을 제가 직접 고르기 위해서 |

## 결과

- 2026.10.18 기준 리포트 데이터 약 1,100건, 종목 276개를 추적 중입니다.
- 운영하며 토큰 한도에 맞춰 수집 주기를 하루 3회(09/12/18시)에서 하루 1회(17:47)로 줄이고, 요약은 실행당 최대 100건으로 상한을 뒀습니다.
- 남이 만든 서비스에 저를 맞추는 대신, 제가 첫 번째 사용자가 되어 필요한 기능을 그때그때 만들어가고 있습니다.

## 한계 (README에 스스로 적어둔 것)

- 삼성·NH·KB·한투·키움·신한은 공개 목록이 없어 아직 수집하지 못합니다.
- 실적 추정치 변화 추적은 하나증권 양식만 읽어, 사실상 한 곳의 시각입니다.
- 논리 평가가 실제로 도움이 되는지는 아직 평가하지 못했습니다. 혼자 쓰는 도구라 평가 기준을 어떻게 잡을지가 열린 문제입니다.
