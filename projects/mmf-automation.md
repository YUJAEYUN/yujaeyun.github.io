# MMF 수익률 취합 자동화

![Type](https://img.shields.io/badge/Type-Internal%20Tool-purple) ![Status](https://img.shields.io/badge/Status-운영%20중-success) ![Period](https://img.shields.io/badge/Period-2026~현재-blue)

**Tech Stack:** Python, LLM API, PowerShell/VBA

---

## Problem

담당자가 운용사 수십 곳의 메일에서 MMF 수익률을 찾아 엑셀로 옮기고 있었습니다. 한 번에 1시간 이상 걸려 주 2회만 갱신했고, 영업 담당자가 최신 수치를 안내하기 어려웠습니다. 요청받은 일은 아니었고, 업무를 지켜보다 자동화를 직접 제안했습니다.

보고서는 운용사마다 표·본문·PDF·이미지로 형식이 달랐고, 같은 값도 잔존만기·듀레이션·잔존일수처럼 다르게 불렸습니다. 어디까지 코드로 전처리하고 어디부터 LLM에 맡겨야 반복 실행해도 같은 결과가 나오는지가 핵심 고민이었습니다.

---

## 구조

- **처음**: 운용사마다 다른 양식을 처리하기 위해 LLM으로 값을 추출하고, 엑셀 입력용 VBA 코드도 LLM이 생성. 운영 중 수익률이 잘못된 열에 입력되는 오류를 발견해, 병합 셀을 미리 정리하는 코드를 추가해 해결.
- **지금**: 메일 수집, 입력 데이터 정리, VBA 기본 구조는 코드로 고정. LLM은 값과 입력 위치를 연결하고 원본과 대조하는 데만 사용. 이상한 값이 발견되면 작업을 중단하고 알림.
- **배포 전 검증**: 수기로 만든 기존 보고서 약 10건(2개월치)과 자동 생성 결과를 대조하며 오류를 수정.
- **운영 중 점검**: 격주로 결과를 직접 점검. 거래 운용사가 바뀌거나 보고서를 다른 메일함으로 보내면 자동화가 오류 없이 조용히 멈출 수 있기 때문이며, 이 점검도 코드로 자동화하는 중.

---

## 선택과 포기

| 선택한 것 | 포기한 것 | 그렇게 판단한 근거 |
|---|---|---|
| LLM 역할을 컬럼 매핑·이상치 검증·자가 보고 세 가지로 한정 | 운용사별 양식 추출 전체를 LLM에 맡김 | 운영 데이터를 보니 같은 운용사의 양식은 거의 바뀌지 않아, LLM 없이도 반복 가능하다는 근거가 쌓임 |
| 이상값 발견 시 작업을 중단하고 알림 | 오류를 무시하고 그대로 진행 | 오류 없이 틀린 결과를 내거나 조용히 멈추는 코드가 가장 위험하다고 판단 |
| 직원들이 쓰던 엑셀 양식을 그대로 유지 | 더 보기 좋은 새 양식으로 교체 | 만든 사람이 옆에 없어도 실무자가 바로 쓸 수 있어야 지속 가능함 |

---

## 결과

- 작업 시간을 1시간 이상에서 약 2분으로 줄이고, 갱신 주기를 주 2회에서 매일로 바꿨습니다.
- 운영해 보니 같은 운용사의 양식이 거의 바뀌지 않는다는 게 확인돼, LLM 없이 업무망의 PowerShell에서 처리하는 방식으로 옮기고 있습니다.

## 한계

거래 운용사가 바뀌거나 보고서를 다른 메일함으로 보내면 자동화가 오류 없이 조용히 멈출 수 있어, 아직은 격주 점검에 기대고 있습니다. 후임자가 유지할 수 있도록 운용사별 수집 스크립트를 생성하는 도구도 함께 만들 계획입니다.
